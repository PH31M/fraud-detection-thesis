# fraud-detection-thesis

Fraud detection thesis project using the PaySim mobile money transaction dataset.

Dataset source: [PaySim1 on Kaggle](https://www.kaggle.com/datasets/ntnu-testimon/paysim1)

```text
fraud-detection-thesis/
├── data/
│   ├── paysim.csv                  # raw dataset downloaded from Kaggle
│   ├── engineered_features.pkl      # generated by notebook 02

│   ├── 01_eda.ipynb
│   ├── 02_feature_engineering.ipynb
│   ├── 03_prepare_dataset.ipynb

```

## Dataset Setup

The raw PaySim dataset is not committed to Git because it is large. To reproduce the project, download it from Kaggle:

[https://www.kaggle.com/datasets/ntnu-testimon/paysim1](https://www.kaggle.com/datasets/ntnu-testimon/paysim1)

After downloading and extracting the dataset, place the CSV file in the `data/` folder and rename it to:

```text
data/paysim.csv
```

The downloaded Kaggle file is commonly named similar to:

```text
PS_20174392719_1491204439457_log.csv
```

Rename it to `paysim.csv` so the notebooks can read it without code changes.

Expected local `data/` folder before running notebooks:

```text
data/
├── paysim.csv
└── .gitkeep
```

Generated files such as `data/engineered_features.pkl` and `data/processed_split.pkl` will be created automatically by the notebooks. They are ignored by Git and should not be committed.

## Notebook Run Order

Run the notebooks in this exact order:

1. `notebooks/01_eda.ipynb`
2. `notebooks/02_feature_engineering.ipynb`
3. `notebooks/03_prepare_dataset.ipynb`
4. `notebooks/04_baseline_models.ipynb`
5. `notebooks/05_extension_smote_xgboost.ipynb`
6. `notebooks/06_shap_cost_sensitive.ipynb`

This order matters because later notebooks depend on artifacts generated by earlier notebooks.

## Pipeline Details

### 1. Exploratory Data Analysis

`notebooks/01_eda.ipynb` reads:

```text
data/paysim.csv
```

It checks:

- dataset shape and column types
- missing values and duplicate rows
- descriptive statistics
- class imbalance between normal and fraud transactions
- fraud distribution by transaction type
- transaction amount distribution
- balance-related anomalies

It saves EDA figures to:

```text
reports/figures/
```

### 2. Feature Engineering

`notebooks/02_feature_engineering.ipynb` reads:

```text
data/paysim.csv
```

It creates fraud-related features:

- `errorBalanceOrig`
- `errorBalanceDest`
- `balance_change_orig`
- `balance_change_dest`
- one-hot encoded transaction type columns

It removes raw identifier columns that are not used for modeling:

- `nameOrig`
- `nameDest`

It writes:

```text
data/engineered_features.pkl
```

### 3. Dataset Preparation

`notebooks/03_prepare_dataset.ipynb` reads:

```text
data/engineered_features.pkl
```

It prepares the modeling dataset by:

- separating features `X` and target `y`
- using `isFraud` as the target label
- dropping `isFlaggedFraud`
- performing a stratified 64:16:20 train/validation/test split
- keeping the test set locked for final reporting
- scaling features with `StandardScaler` fitted on the training set only

It writes:

```text
data/processed_split.pkl
```

### 4. Baseline Models

`notebooks/04_baseline_models.ipynb` reads:

```text
data/processed_split.pkl
```

It trains and evaluates baseline models:

- Logistic Regression
- KNN
- Decision Tree
- Random Forest

It writes:

```text
results/baseline_results.csv
results/baseline_models.pkl
```

### 5. XGBoost and SMOTE Extension

`notebooks/05_extension_smote_xgboost.ipynb` reads:

```text
data/processed_split.pkl
```

It trains:

- XGBoost without imbalance handling
- XGBoost with SMOTE

SMOTE is applied only to the training set, not to the test set.

It writes:

```text
results/xgb_vs_xgb_smote_comparison.csv
results/xgb_plain_model.pkl
results/xgb_smote_model.pkl
results/xgb_models.pkl
results/train_smote_summary.csv
```

### 6. SHAP and Cost-Sensitive Evaluation

`notebooks/06_shap_cost_sensitive.ipynb` loads the saved models and performs:

- SHAP summary plot generation
- SHAP force plot generation for selected cases
- cost-sensitive evaluation
- threshold sweep analysis

It performs cost-sensitive evaluation with the following split policy:

- `cost_sensitive_comparison.csv`: baseline comparison on the test set with fixed threshold `0.5`
- `cost_sensitive_threshold_sweep.csv`: threshold sweep on the validation set only
- `cost_sensitive_best_thresholds.csv`: thresholds selected from validation, including their selection split
- `cost_sensitive_test_final.csv`: final test metrics using thresholds selected from validation
- `cost_sensitive_sensitivity.csv`: descriptive sensitivity analysis at fixed threshold `0.5`

The threshold-selection workflow is:

```text
train models -> select threshold on validation -> lock threshold -> report once on test
```

It writes:

```text
results/shap_summary_plot.png
results/shap_force_plot_TP.png
results/shap_force_plot_FN.png
results/cost_sensitive_comparison.csv
results/cost_sensitive_sensitivity.csv
results/cost_sensitive_sensitivity.png
results/cost_sensitive_threshold_sweep.csv
results/cost_sensitive_best_thresholds.csv
results/cost_sensitive_test_final.csv
```

## Important Generated Files

These files are generated locally and are not committed:

```text
data/paysim.csv
data/engineered_features.pkl
data/processed_split.pkl
```

If `data/engineered_features.pkl` is missing, run:

```text
notebooks/02_feature_engineering.ipynb
```

If `data/processed_split.pkl` is missing, run:

```text
notebooks/03_prepare_dataset.ipynb
```

If a downstream notebook fails with a missing artifact error, run the previous notebook first.

## Reproduce from Scratch

1. Clone this repository.
2. Download the PaySim dataset from Kaggle.
3. Extract the downloaded file.
4. Rename the raw CSV to `paysim.csv`.
5. Put it under `data/paysim.csv`.
6. Create a virtual environment.
7. Install dependencies with `pip install -r requirement.txt`.
8. Run notebooks `01` to `06` in order.
9. Check generated figures in `reports/figures/`.
10. Check generated model outputs and evaluation tables in `results/`.

## Notes

- The dataset and intermediate `.pkl` files are intentionally ignored by Git.
- `engineered_features.pkl` is generated by `02_feature_engineering.ipynb`.
- `processed_split.pkl` is generated by `03_prepare_dataset.ipynb`.
- The notebook numbering matches the real execution order.
- `02_feature_engineering.ipynb` and `03_prepare_dataset.ipynb` do not depend on variables left in memory from previous notebooks.
- Baseline, XGBoost, SHAP, and cost-sensitive evaluation run as one numbered pipeline.
